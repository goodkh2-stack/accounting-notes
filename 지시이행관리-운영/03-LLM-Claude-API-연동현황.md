# 03. Claude API 연동 부분 및 LLM 사용 기능 정리

## 1. 현재 상태: 미구현

**현재 `directive-tracker.html` 코드에는 Claude API(또는 어떤 LLM API)를 호출하는 코드가 전혀 없습니다.**

확인 근거:
- 코드 전체에 `fetch(`, `XMLHttpRequest`, `axios` 등 네트워크 호출 코드 없음
- `anthropic`, `claude`, `api.anthropic.com`, API 키 관련 코드/설정 없음
- 백엔드 서버 자체가 없으므로(01번 문서 참고) API 키를 안전하게 보관·중계할 위치도 없음

즉, 회의록 내용에서 지시사항을 자동 추출하거나, 챗봇으로 이행 현황을 질의응답하는 등의 **LLM 기반 기능은
아직 어떤 형태로도 구현되어 있지 않습니다.** 현재 시스템은 사용자가 직접 폼을 채워 넣는 수기 입력 방식으로만
동작합니다.

## 2. 이전 논의 경과

이전 세션에서 "서버/LLM 연결 구조 아키텍처 설계"를 요청받아 백엔드 언어, LLM 용도, 배포 환경에 대한
확인 질문을 드렸으나 **사용자가 답변을 보류(dismiss)** 하여 실제 아키텍처 설계 및 구현은 진행되지 않았습니다.
따라서 아래 3절은 "이후 구현 시 검토할 수 있는 방향성 제안"이며, 코드로 반영된 결정 사항이 아닙니다.

## 3. 향후 연동 시 검토할 설계 방향 (제안, 미확정)

LLM 연동을 추가하려면 최소한 아래 이유로 **백엔드 서버 계층 신설이 필요**합니다.

- Claude API 키를 브라우저(클라이언트) 코드에 직접 넣으면 누구나 개발자 도구로 키를 탈취할 수 있음 →
  반드시 서버를 경유해 키를 서버 환경변수로만 보관해야 함
- 브라우저에서 `api.anthropic.com`으로 직접 CORS 요청은 지원되지 않음

### 3.1 제안 아키텍처 (구현 전 초안)

```
[브라우저: directive-tracker.html]
        │  fetch('/api/directives/extract', {회의록 텍스트})
        ▼
[백엔드 서버: Node.js/Express 또는 Python/FastAPI 등 — 미정]
        │  Anthropic 공식 SDK로 Claude API 호출
        │  (API 키는 서버 환경변수 ANTHROPIC_API_KEY로만 보관)
        ▼
[Claude API (claude-opus-5 등)]
        │  구조화 출력(output_config.format)으로
        │  {title, instructorRole, assignee, priority, dueDate, ...} JSON 반환
        ▼
[백엔드가 결과를 브라우저에 반환 → 지시사항 등록 폼에 자동 채움]
```

### 3.2 검토 가능한 LLM 활용 시나리오 (미구현, 후보)

| 시나리오 | 설명 |
|---|---|
| 회의록 → 지시사항 자동추출 | 회의 내용 텍스트를 Claude에 전달, 구조화 출력으로 지시사항 후보 목록(JSON)을 받아 폼에 자동 채움 |
| 회의록 요약 | 긴 회의 내용을 핵심 요약본으로 압축 |
| 이행 현황 Q&A 챗봇 | "이번주 지연된 지시사항 뭐야?" 같은 자연어 질의에 현재 데이터 기반으로 답변 |

### 3.3 다음 단계로 필요한 결정 사항 (사용자 확인 필요, 아직 미정)

1. 백엔드 언어/스택 (Node.js+Express / Python+FastAPI / 서버리스 등)
2. LLM 활용 범위 (위 3.2 중 어떤 것을 먼저 구현할지)
3. 서버/데이터 배포 위치 (클라우드 vs 사내/로컬 서버)
4. 여러 사용자 간 데이터 공유가 필요한지 (필요하다면 localStorage를 DB로 교체하는 작업이 선행되어야 함)

이 결정이 내려지면 실제 서버 코드, API 엔드포인트, 프롬프트 설계를 포함한 구현 문서를 이 폴더에 추가할
예정입니다.
