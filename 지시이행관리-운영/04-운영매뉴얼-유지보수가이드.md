# 04. 운영 매뉴얼 및 유지보수 가이드

## 1. 사용자용 운영 매뉴얼

### 1.1 접속 방법
- **로컬 사용**: 저장소를 내려받아 `directive-tracker.html` 파일을 더블클릭하거나 브라우저로 열기
- **웹으로 배포한 경우**: 배포된 URL로 접속 (현재 저장소는 아직 정적 호스팅에 배포되어 있지 않음 — 01번 문서 참고)
- 별도 로그인/계정 없음. 파일에 접근할 수 있는 사람은 누구나 사용 가능

### 1.2 기본 사용 흐름
1. **회의록** 탭 → "새 회의록"으로 회의 일자/구분/참석자/내용 입력 후 저장
2. 회의록 목록에서 "지시사항추가"를 눌러 해당 회의에서 나온 C레벨 지시사항을 등록
   (지시자, 담당자, 우선순위, 마감일, 상태 입력)
3. 진행 상황이 바뀔 때마다 지시사항을 편집 → 상태 변경 + 경과 메모 입력 후 저장
   → 자동으로 "이행 이력"에 기록됨
4. **대시보드**에서 지연/임박 건과 전체 통계를 수시로 확인

### 1.3 데이터 백업 (필수 습관)
모든 데이터는 브라우저 `localStorage`에만 저장되므로, **브라우저 캐시/데이터를 지우면 모든 기록이
사라집니다.**

- 헤더의 **"데이터 내보내기"**를 주기적으로(예: 매주) 눌러 JSON 파일로 저장해 두세요.
- 다른 PC/브라우저로 옮기거나 데이터가 유실됐을 때는 **"가져오기"**로 백업 파일을 불러오면 복구됩니다.
  (가져오기는 현재 데이터를 전부 덮어쓰므로 주의)

### 1.4 여러 사람이 함께 쓰려면
현재 구조는 브라우저별로 데이터가 독립되어 있어 **자동으로 공유되지 않습니다.** 팀에서 함께 쓰려면:
- (임시) 한 사람이 입력 후 "내보내기"한 JSON을 공유하고 다른 사람이 "가져오기"로 동기화, 또는
- (근본 해결) 서버+데이터베이스를 도입해 실시간 공유 — 03번 문서의 향후 설계 방향 참고

## 2. 장애 대응 (트러블슈팅)

| 증상 | 원인 후보 | 대응 |
|---|---|---|
| 저장했는데 목록에 안 보임 | 브라우저가 시크릿/프라이빗 모드라 localStorage가 세션 종료 시 삭제됨 | 일반 모드로 사용, 저장 직후 내보내기로 백업 |
| 데이터가 갑자기 사라짐 | 브라우저 캐시/사이트 데이터 삭제, 다른 브라우저·기기로 접속 | 최근 백업 JSON으로 "가져오기" 복구 |
| 화면이 깨지거나 버튼이 안 눌림 | 브라우저 JS 콘솔 에러 (오래된 브라우저, 확장 프로그램 충돌) | 최신 Chrome/Edge/Firefox로 재시도, 콘솔(F12) 에러 로그 확인 |
| 가져오기 실패 알림 | JSON 형식이 `{meetings:[...], directives:[...]}` 구조가 아님 | 반드시 이 시스템에서 "내보내기"한 파일만 가져오기에 사용 |

## 3. 코드 유지보수 가이드 (개발자용)

### 3.1 수정 원칙
- 파일 하나(`directive-tracker.html`)에 HTML/CSS/JS가 모두 들어있으므로, 수정 시 어느 섹션인지
  먼저 확인(01번 문서의 "코드 구조" 표 참고) 후 해당 부분만 수정
- 상태 값 문자열("대기", "진행중" 등)은 HTML `<select>`의 `<option>`과 CSS의 `.status-<값>` 클래스,
  JS 로직 세 곳에 모두 하드코딩되어 있음 → **상태/우선순위 값을 추가·변경할 때는 이 세 곳을 함께 수정**
  1. HTML: `<select id="directiveStatus">` (또는 필터용 select)의 `<option>`
  2. CSS: `.badge.status-새값 { background: ...; }`
  3. 필요 시 JS의 상태 관련 로직(예: `isOverdue()`)
- `escapeHtml()`을 거치지 않고 사용자 입력을 `innerHTML`에 직접 넣지 않도록 주의(XSS 방지) —
  새로운 렌더 함수를 추가할 때도 동일하게 이스케이프 처리할 것

### 3.2 로컬 검증 방법
빌드 도구가 없으므로 아래로 최소 검증합니다.

```bash
# JS 문법 오류만 빠르게 확인 (브라우저 API는 검증 안 됨, 문법만 체크)
node -e "
const fs = require('fs');
const html = fs.readFileSync('directive-tracker.html', 'utf8');
const match = html.match(/<script>([\s\S]*)<\/script>/);
fs.writeFileSync('/tmp/check.js', match[1]);
"
node --check /tmp/check.js
```

실제 동작 확인은 브라우저로 파일을 열어 각 탭(대시보드/회의록/지시사항)에서 등록·편집·삭제·필터·
내보내기/가져오기를 수동으로 테스트합니다. 별도의 자동화 테스트 스위트는 아직 없습니다.

### 3.3 데이터 마이그레이션 시 주의
localStorage 키에 `_v1` 접미사가 붙어 있는 이유는 향후 스키마가 바뀔 때 `_v2` 키로 전환하며
이전 데이터를 변환하는 마이그레이션 로직을 넣을 수 있게 하기 위함입니다. 스키마를 바꿀 때는:
1. 새 키(`meetings_v2` 등)를 정의
2. 앱 시작 시 구버전 키가 있으면 새 스키마로 변환해 새 키에 저장하는 마이그레이션 함수 추가
3. 문서(02번)의 스키마 표를 함께 갱신

### 3.4 배포 절차 (정적 호스팅 예시: GitHub Pages)
현재 미설정 상태이며, 필요 시 아래 절차로 배포할 수 있습니다(적용 전 사용자 확인 필요).
1. 저장소 Settings → Pages → 배포 브랜치/폴더 지정
2. `directive-tracker.html`을 `index.html`로 복사하거나 별도 경로로 지정
3. (주의) 현재 루트의 `index.html`은 이미 다른 프로젝트(회계학 노트)가 쓰고 있으므로 충돌 여부 확인 필요
