# 01. 환경 / 서버 / 코드 구조 문서화

## 1. 전체 아키텍처 개요

현재 시스템은 **서버가 없는 순수 정적 프론트엔드 애플리케이션**입니다.

```
┌─────────────────────────────────────────────┐
│                   사용자 브라우저                │
│                                               │
│   directive-tracker.html                     │
│   ├── HTML  : 화면 구조 (대시보드/회의록/지시사항) │
│   ├── CSS   : 인라인 <style> (디자인 토큰, 반응형) │
│   └── JS    : 인라인 <script> (즉시실행함수 IIFE)  │
│        ├── 데이터 레이어 (localStorage read/write)│
│        ├── 렌더 함수 (화면 그리기)                │
│        └── 이벤트 핸들러 (버튼/폼 처리)            │
│                                               │
│   저장소: window.localStorage                 │
│   ├── meetings_v1    (회의록 배열, JSON)        │
│   └── directives_v1  (지시사항 배열, JSON)       │
└─────────────────────────────────────────────┘
        ↑ 백엔드 서버 없음 / API 호출 없음 ↑
```

- **백엔드 서버: 없음.** Node.js, Python 등 어떤 서버 프로세스도 존재하지 않습니다.
- **데이터베이스: 없음.** 모든 데이터는 브라우저의 `localStorage`에만 저장됩니다.
- **외부 API 호출: 없음.** 네트워크 요청을 보내는 코드가 없습니다(LLM 포함).
- **빌드 도구: 없음.** `npm`, 번들러, 트랜스파일러 없이 파일을 그대로 브라우저가 실행합니다.

## 2. 코드 구조 (`directive-tracker.html` 내부)

단일 HTML 파일이며, 아래와 같이 3개 영역으로 구성됩니다.

### 2.1 HTML 구조
```
<header>                 상단 타이틀 + 데이터 내보내기/가져오기 버튼
<nav class="tabs">       대시보드 / 회의록 / 지시사항 이행관리 탭
<main>
  <section id="view-dashboard">   대시보드 화면
  <section id="view-meetings">    회의록 목록 화면
  <section id="view-directives">  지시사항 목록 화면
<div id="meetingModalBackdrop">   회의록 등록/편집 모달
<div id="directiveModalBackdrop"> 지시사항 등록/편집 모달
<script> ... </script>            애플리케이션 로직 전체
```

### 2.2 JavaScript 구조 (IIFE 내부, 역할별 섹션)

| 섹션 | 역할 |
|---|---|
| **데이터 레이어** | `loadList()`, `saveList()`, `uid()`, `todayStr()` — localStorage 입출력, ID/날짜 생성 |
| **도메인 헬퍼** | `isOverdue()`, `effectiveStatus()`, `directivesForMeeting()`, `escapeHtml()` — 지연 판정, XSS 방지용 이스케이프 |
| **탭 네비게이션** | 탭 버튼 클릭 시 `.view` 표시/숨김 전환 |
| **대시보드 렌더** | `renderDashboard()` — 통계 카드, 마감 임박/지연 목록, 최근 회의록 |
| **회의록 뷰** | `renderMeetings()`, `openMeetingModal()`, `closeMeetingModal()` + 저장/삭제 이벤트 |
| **지시사항 뷰** | `renderDirectives()`, `openDirectiveModal()`, `closeDirectiveModal()` + 저장/삭제 이벤트, 필터/검색 |
| **내보내기/가져오기** | `Blob`/`FileReader` 기반 JSON 백업 다운로드·업로드 |
| **초기화** | 파일 로드 시 `renderDashboard()` 최초 실행 |

전역 상태는 모듈 스코프의 `meetings`, `directives` 배열 두 개이며, 모든 렌더 함수는 이 배열을 읽어 DOM을
`innerHTML`로 다시 그리는 방식(리렌더링)으로 동작합니다. 별도 프레임워크(React 등) 없이 바닐라 JS로 구현되어
있습니다.

## 3. 실행/배포 방식

- **로컬 실행**: `directive-tracker.html` 파일을 브라우저로 직접 열면 바로 동작합니다(서버 불필요).
- **정적 호스팅 배포**: GitHub Pages, Netlify, Vercel(정적 사이트) 등에 파일 그대로 올리면 URL로 접근 가능합니다.
  현재 저장소에는 GitHub Pages 설정(`gh-pages` 브랜치, `_config.yml` 등)이 되어 있지 않아 **아직 배포되어 있지
  않습니다.**
- **CI/CD**: 없음. 별도의 GitHub Actions 워크플로우가 구성되어 있지 않습니다.

## 4. 왜 서버가 없는가 (설계 배경)

이 시스템은 "구성원 개인이 브라우저에서 바로 쓸 수 있는 가벼운 도구"를 목표로, 기존 저장소의
`index.html`(정적 학습 노트)과 동일한 방식(빌드 없는 순수 HTML)으로 만들어졌습니다. 이 때문에:

- 장점: 배포가 매우 단순(파일 하나), 서버 운영 비용 없음, 오프라인에서도 동작
- 한계: 여러 사람이 데이터를 공유할 수 없음(브라우저별로 격리), API 키를 안전하게 보관할 백엔드가 없어
  LLM 연동을 하려면 서버 계층을 새로 추가해야 함 (03번 문서 참고)
